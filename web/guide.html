Запуск за минуту

  1. Распакуйте архив. Установите JDK 21 или новее и добавьте java / javac в PATH либо задайте JAVA_HOME.
  2. В Windows запустите start-local.cmd. В Linux/macOS: BLUEPRINTS_RUNNER=local sh start.sh.
  3. Откройте http://localhost:8080.
Windows:  .\start.ps1 -TrustedLocal
Docker:   docker compose up --build
Tests:    python tests/test_api.py
Trusted local предназначен для собственных исходников. Дочерняя JVM не ограничивает доступ к файловой системе и сети ОС. Отдельный Docker runner запускается флагом -Docker после подготовки образа eclipse-temurin:21-jre. Docker-путь в текущей среде не проверен.

Что демонстрировать

  1. Выберите countPairs: два вложенных цикла и привязанный к строке диагноз.
  2. Примените оптимизацию: индекс частот заменяет повторный обход. Среднее время O(n), память O(k).
  3. Запустите gate: две сборки и новая JVM для каждого входа. Сравниваются исходные байты stdout/stderr и exitCode.
  4. Измените условие classify: n == 0 → n == 1. Gate обнаружит изменение результата.
  5. Отмените правку, выделите countPairs в BlueprintFunctions.java и проверьте снова.
  6. Экспортируйте Java-файлы, эталон, входы и отчёт в ZIP. Повторите на монолите на 1052 строки.

Архитектура

Java source → JavacTask.parse() → AST + SourcePositions
                         ↓
          GraphBuilder / Analyzer / Transformations
                         ↓
         Source-preserving patch → Java source
                         ↓
     javac baseline + javac candidate → separate JVMs
                         ↓
            stdout + stderr + exitCode → gate

Реализованный scope

ОбластьПоддержка
JavaСтандартный javac 21: классы, интерфейсы, поля, конструкторы, примитивы, массивы, управляющие конструкции, исключения, стандартная библиотека. Record, enum, generics, lambda и Stream сохраняются и компилируются.
ГрафВетвления, циклы, switch, break/continue/return. Правка инструкций, условий, вставка и удаление. Нет произвольной коммутации рёбер.
ДиагностикаВложенность циклов, длинные методы, пустой catch, += в цикле, строковый литерал в сравнении ссылок. Big O - структурная эвристика.
ОптимизацияТочный чистый AST-шаблон подсчёта равных упорядоченных пар int[]. Дополнительные эффекты отклоняют замену.
ДекомпозицияНезависимый static-метод → helper-файл с проверкой зависимостей компиляцией.
Тесты22 реальных интеграционный сценарий: случайные входы, ошибки сборки, намеренный FAIL, таймаут, flood вывода, raw bytes, монолит 1052 строки.

Границы гарантий

Финитные тесты подтверждают поведение на выбранных входах, но не доказывают эквивалентность на всех возможных данных. Граф исключений консервативный, переходы через finally и метки показаны структурно. Big O не учитывает стоимость вызовов и реальные границы циклов. Перенос метода меняет стек вызовов. Оптимизация использует дополнительную память.
